Known gotchas for this migration

High Position-based versus job-based models

If Workday position management is in use, the target job-based model needs a deliberate mapping of positions, requisitions, and headcount plans.

High Integration Cloud replacements

EIBs, Core Connectors, and Studio integrations must each map to a target connector, API, or file feed. Inventory by system and by owner, and expect orphans.

High Calculated fields and custom reports

Workday calculated fields and composite reports used by Finance and HR have no direct equivalent. Rebuild against target reporting and reconcile headcount to the old numbers.

High Workday as IdP provisioning hub

If Workday drives joiners and leavers into the IdP, the handoff to the new HR source must be tested before it replaces the feed.

Critical Cutover dates belong to payroll, not IT

A mid-quarter or mid-year payroll move forces year-to-date wage imports and complicates tax filings. Anchor the schedule on a quarter or year boundary and work backward.

High Effective-dated history

Source systems keep dated job, comp, and org history. Decide how much history is imported versus archived, and keep the source read-only for lookups and audits.

High Worker ID continuity

Downstream systems key on employee ID. Keep a source-to-target mapping table and test every consumer against it.

High Benefits carriers have their own calendars

Carrier file changes take weeks to validate, and open enrollment timing may forbid changes. Start carrier testing at project kickoff.

High Business processes and security roles do not port

Approval chains, delegations, and role-based data access (especially compensation) must be rebuilt and access-reviewed. Over-permissioned defaults are a common leak.

High Compliance retention outlives the contract

I-9 and personnel records have statutory retention periods. Confirm the archive keeps them reachable after the old subscription ends.

Medium Ownership overlap with IT products

Some HRIS vendors also sell identity and device management. Decide explicitly whether to adopt them or keep your IdP and MDM, so ownership is not ambiguous.

Info Verify vendor behavior

Integration catalogs and payroll coverage change by release and state. Confirm every Critical and High item with the vendor in writing.

Decisions to record (ADRs)

  • Cutover boundary: Year start / Quarter start / Mid-period with YTD import
  • History depth: Full effective-dated history / Two years plus archive / Current state plus read-only archive
  • Adopt vendor IT products or keep existing IdP and MDM: Keep existing / Adopt vendor identity/devices / Phase decision after HRIS stabilizes

Phases

1. Discover and decide
  • Inventory every consumer of employee data
  • Fix cutover quarter with Payroll and Finance
  • Decide history depth and archive approach
  • Record decisions as ADRs
2. Build and map
  • Configure org, jobs, comp, and security in the target
  • Build data mapping and ID continuity table
  • Rebuild integrations and reports in the target
3. Validate and parallel run
  • Load test data and reconcile
  • Run parallel payroll cycles until clean
  • Validate carrier files and accounting journals
4. Cut over and stabilize
  • Execute cutover on the agreed boundary
  • Hypercare through first full pay cycle and first close
  • Archive source and complete access review

Cutover day checklist

  • Payroll sign-off from two parallel runs with zero unexplained variance
  • Benefit carriers confirm accepted files
  • Open transactions and approvals drained in the source
  • Source system frozen to changes at an agreed time
  • Downstream feeds switched in dependency order
  • Security roles and compensation access reviewed
  • Employee and manager communication delivered

Rollback

  • Before the point of no return (first live payroll), the source remains system of record and the target load is discarded
  • After first live payroll, rollback is a forward fix: define the manual payroll fallback and who authorizes it
  • Integrations: keep source feeds ready to re-enable for each consumer

Exit criteria

  • Two clean live pay cycles and one clean accounting close
  • All consumers receive data from the new source
  • Carrier reconciliations clean for one billing cycle
  • Source system archived read-only with documented retention owner

How to build the inventory

  • Workday: list all integration systems (EIBs, Core Connectors, Studio) with schedules and owners from the integrations report
  • Workday: export custom reports and calculated fields with last-run date and audience
  • Workday: export business process definitions and security groups with membership
  • Payroll: calendar of pay periods, tax filing dates, and year-end processing
  • Benefits: carrier list, file formats, plan year dates, open enrollment window
  • Finance: GL mapping, cost center list, and recurring HR-driven reports
  • Ask IT for every system that consumes employee data (IdP, ATS, LMS, expense, Slack)
