Known gotchas for this migration

High Smart groups and extension attributes

Scoping built on Jamf smart groups and extension attributes needs a different mechanism in Kandji (blueprints and tags). Map scoping logic before porting individual items.

High Policies versus library items

Jamf policies with triggers do not map one to one to Kandji library items and automations. Redesign by outcome, not by object.

High Login window and Jamf Connect

If Jamf Connect manages login and account creation, choose and test a replacement before moving those devices.

Critical One MDM at a time

A device cannot be managed by two MDMs. During the swap it has no management, so network, security agent, and encryption profiles must land the moment enrollment completes.

Critical FileVault recovery keys are held by the old MDM

Keys escrowed in the old platform become unreachable once it is gone. Rotate and re-escrow to the target before removing the old enrollment, and test recovery.

Critical Activation Lock exposure

Wiping or removing management without handling Activation Lock bypass codes can brick org-owned devices. Confirm how each fleet segment is protected before any wipe.

High Enrollment method decides the user experience

Recent OS releases add a managed MDM migration path for ADE devices without a wipe; older releases may need unenroll and re-enroll, an erase, or user action. Verify OS minimums and both vendors' current support for each device segment.

High Certificates tied to the old MDM

Device identity certificates issued through the old MDM's SCEP/ACME path break Wi-Fi, VPN, and device trust when it goes away. Reissue before cutover.

High Security agents need re-approval

Privacy and system extension approvals are delivered by profile. If they are missing at enrollment, the agent can lose protection or show the user prompts.

Medium Remote workers and non-ADE devices

Devices outside the office or enrolled by users need a self-driven path with clear instructions and helpdesk support. Plan for stragglers and a deadline.

Medium Scripts are hidden business logic

Years of policies and scripts quietly enforce settings and fixes. Audit them with owners; some should be retired, not ported.

Decisions to record (ADRs)

  • Migration method per device segment: Managed migration without wipe / Unenroll and re-enroll / Erase and reprovision / User-driven enrollment
  • Login window and account strategy: Keep current tool / Replace with target equivalent / Move to IdP-native device login
  • Scripts and policies: Port 1:1 / Redesign by outcome / Retire unused

Phases

1. Discover and decide
  • Inventory profiles, scripts, scopes, and certificates
  • Segment the fleet by enrollment method and OS
  • Retire dead policies before porting
  • Record decisions as ADRs
2. Build and pilot
  • Stand up the target MDM and mirror configuration
  • Verify escrow, certificates, and security agent in a lab
  • Migrate IT devices as pilot
3. Migrate in waves
  • Move device groups in the generated order
  • Verify health after every wave
  • Handle stragglers with a deadline and escalation
4. Decommission
  • Remove old MDM tokens and integrations
  • Archive configuration and logs
  • Update runbooks and compliance evidence

Cutover day checklist

  • Recovery keys and bootstrap tokens verified in the target for wave devices
  • Network, certificate, and security agent profiles confirmed to land at enrollment
  • Activation Lock handling confirmed for every device in the wave
  • Apple Business Manager assignment step rehearsed
  • User instructions sent with deadline and helpdesk contact
  • Pilot device passed full reboot, login, VPN, and agent health test
  • Success metric defined (enrolled, compliant, agent healthy)

Rollback

  • Before ABM reassignment: re-enroll the device in the old MDM using the saved profiles
  • Keep the old MDM instance and tokens intact until the final wave completes
  • Per wave: documented steps to pause and revert ABM assignment and restore previous enrollment where supported
  • Escalation path for devices stuck unmanaged

Exit criteria

  • 100 percent of in-scope devices checked in to the new MDM
  • No devices checking in to the old MDM for 30 days
  • Escrow, certificates, and security agent verified fleet-wide
  • Old MDM decommissioned with archived configuration

How to build the inventory

  • Jamf: API or export of computers, mobile devices, configuration profiles, policies, scripts, packages, smart groups, extension attributes
  • Jamf: scope and last-execution data for policies to find dead ones
  • Kandji: export of devices, blueprints, library items, and custom scripts
  • Apple Business Manager: device assignments, MDM servers, and Apps and Books tokens
  • Security: EDR vendor's current deployment profile, PKI/SCEP/ACME configuration
  • Network team: Wi-Fi and VPN authentication method and certificate dependencies
  • Fleet segmentation: ADE versus manual, OS versions, supervised state, remote versus on-site
